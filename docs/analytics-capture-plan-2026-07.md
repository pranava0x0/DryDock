## 1. Executive summary

The user's ask, distilled: **"Track how I'm doing"** across three AI subscriptions (Claude Max, ChatGPT Plus/Codex, Google AI Pro/Antigravity) and all GitHub work (public + private) — model/app preferences, usage patterns, spend vs. subscription — **plus make the backlog durable and effortless to feed** (more durable than a Notes list; capture by text/Siri/email-reply), **and link the satellites** (Daily Briefing, autogenerated-ideas) so ideas, briefings, and the backlog form one loop.

Three findings change what's buildable:

1. **All three providers have parseable local data on this Mac — the "not trackable" verdict is obsolete.** DD-BL-22 Phase 2b was deferred as "not pursuable" because ChatGPT Plus and Google AI Pro expose no usage API. True for APIs — but `~/.claude/projects` (1,673 session JSONLs, 1.3 GB, per-message `model` + full token usage), `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` (103 files, per-turn `token_count` deltas + `cwd` + originator), and `~/.gemini/antigravity/brain/*/.system_generated/logs/transcript.jsonl` (per-conversation steps, timestamps, model-selection breadcrumbs) are all on disk, and `lib/providers/{claude,codex,gemini}-usage.ts` **already parse them** into rolling windows. What's missing is not acquisition — it's **history** (windows are recomputed, never persisted — and Claude Code session logs rotate out after ~30 days by default (`cleanupPeriodDays`), so unpersisted history is actively evaporating), **dimensions** (no per-model / per-project / hour-of-day), and a **dashboard** (Settings cards are the only surface). Live **quota %** (the number the caps actually gate on) also turns out to be locally reachable without scraping: Codex ships a JSON-RPC `app-server` (`account/rateLimits/read`) that rides `~/.codex/auth.json`, and Claude Code maintains `~/.claude/stats-cache.json` (the pre-aggregated store behind `/usage`, exempt from the 30-day sweep). The remaining gap — claude.ai/chatgpt.com/gemini web-chat usage and subscription/billing facts — is covered by official exports and an optional scheduled browser-collector (EP-15), not APIs.
2. **Claude Code session logs contain `pr-link` records** (`{sessionId, prNumber, prRepository, prUrl}`) — an **exact** session↔PR join, no time-window heuristics. Combined with commit trailers (`Co-Authored-By: Claude <model> <noreply@anthropic.com>` — model name embedded; Codex's static `Co-authored-by: Codex <noreply@openai.com>`), branch conventions (`drydock/*` has ground-truth provider on the task row; `claude/*`; `jam/*` — a second orchestrator, seen across 7 repos), and `repo`-scoped GraphQL over all 34 repos (27 public, 7 private), a private-inclusive "how much of my shipped code is AI, by which agent, trending weekly" chart is directly computable.
3. **The backlog architecture extends; it does not change.** Hub-and-spoke with SQLite as hub is already how Apple Notes sync works, and every hard-won invariant (id-stable targeting, `external_id` stamping, mutex, DB-wins-on-push) generalizes. GitHub Issues become a **second spoke** (single tracker repo), capture channels become **inbound feeders** through a new *inbox* stage, and the satellites connect through the **MCP server DD-BL-34 already scoped** — whose own stated blockers (EP-1 auth, EP-2 threads) shipped in PR #7, so it is now unblocked.

The track: **persist the telemetry → open the dashboard → make capture instant → mirror to GitHub Issues → link the fleet → top up with exports/scrape.** Phase 0 hygiene first (a security upgrade is overdue — §3).

## 4. Architecture: the modular frame

Everything in this track plugs into four module families. Each family has a registry (the `lib/providers/index.ts` pattern: typed key union + `REGISTRY` map + `isX()` guard), lives in its own directory, and is independently testable. This is the "expand later without rework" answer: a new provider log, a new capture channel, a new sync target, or a new dashboard card is one module + one registry line.

```
                     ┌───────────────────────────── DryDock (Next.js, SQLite hub) ─────────────────────────────┐
  COLLECTORS (pull)  │  lib/connectors/*  — read-only gatherers → rollup tables                                 │
  claude-jsonl ────► │   usage_daily, ai_sessions          ┌──────────────┐                                    │
  codex-jsonl ─────► │   gh_repos/gh_commits/gh_prs ─────► │   SQLite     │ ◄──── SPOKES (bidirectional sync)   │
  antigravity ─────► │   gh_daily_stats                    │  (canonical) │       lib/integrations/*            │
  github-graphql ──► │                                     │              │       apple-notes (existing, sacred)│
  exports/browser ─► │  (EP-15, degradable)                └──────┬───────┘       github-issues (EP-13)         │
                     │                                            │                                             │
  CHANNELS (inbound) │  POST /api/capture → inbox (triaged_at NULL) │              INSIGHT (read)                │
  PWA quick-add ───► │  Shortcut/Siri ─► same endpoint              │              lib/insights/* → /analytics   │
  iMessage poller ─► │  ideas connector (source='ai-generated') ────┘              tabs: Runs | Usage | Flow     │
  (email-reply: later)                                                                                          │
                     │  MCP SERVER (stdio, EP-14): add_backlog_item · list_backlog · burn_down_item ·           │
                     │  list_tasks · get_task_status · get_usage_stats   (dispatch_task gated)                  │
                     └──────────────────────────────────────────────────────────────────────────────────────────┘
```

**Conventions (binding, from the base plan + AGENTS.md):** schema changes in `lib/db/schema.sql` **and** `ensure()` in `migrate()`; mutations only through `lib/db/*.ts`; new routes `runtime = "nodejs"`; invariants in the DB, not the UI; fail loud, never render a confident wrong value; bounded I/O with timeouts; one regression test per bug; mobile-first 375×812, touch ≥ 44px; **no API keys, ever** — `gh` CLI, `osascript`, local files, and the existing `DRYDOCK_AUTH_TOKEN` are the only credentials, and the browser-collector (EP-15) runs inside a Claude Code session using the user's own logged-in browser, never stored credentials.

**Collector cadence without a scheduler.** EP-8 (in-process scheduler) hasn't shipped. Until it does, collectors run **on-read with TTL** — exactly how `/api/provider-budgets` works today (60s in-process cache): `GET /api/usage` and `GET /api/flow` trigger a collect if stale (per-collector TTL: local-file collectors 60s gated by the existing `usage-mtime` cheap check; GitHub 5 min). One shared in-process mutex per collector (the `inFlightSync` pattern) so concurrent readers share a run. **No new client-side auto-sync triggers** — the CLAUDE.md rule stands; the Analytics page fetches on mount + the existing throttle-gate interaction pattern from Settings. When EP-8 lands, the same collector interface gets a server tick for free.

```ts
// lib/connectors/types.ts
export interface Connector {
  key: ConnectorKey;                       // "claude-local" | "codex-local" | "antigravity-local" | "github" | ...
  ttlMs: number;
  collect(db: Database, opts: { force?: boolean }): Promise<CollectResult>;  // incremental via its own watermark
  health(): Promise<ConnectorHealth>;      // "ok" | "no-data" | "unavailable" (+ reason) — surfaced, never hidden
}
```

**Watermarks** live in `settings` (`connector.<key>.last_sync_at`, `connector.<key>.cursor`) — the `apple_notes_last_sync_at` pattern, one keyspace per connector.

**Security posture for this track** (sources ranked; applies everywhere):
1. **Local files** (all EP-10/11 sources): read-only, numeric aggregation, content never stored beyond titles the user owns. Zero external risk.
2. **`gh` CLI / GraphQL**: user's own token, read-only queries, 1-point costs against a 5,000/hr budget.
3. **Official exports** (EP-15): user-initiated, zero ToS risk, high latency.
4. **Scheduled authed-browser collection** (EP-15): the user's own logged-in browser reading the user's own account pages (claude.ai/settings/usage, ChatGPT/Google plan pages). Fragile by nature (DOM changes) and automation of consumer web UIs sits in a ToS gray zone — so it is **optional, last, and degradable**: every consumer renders "manual entry / deep-link" when the collector has no fresh data. First-party pages only; no third-party extensions (the PromptSnatcher/ClaudeBleed advisory class — chat-stealing browser extensions — is the cautionary tale; see `vibe-coding-security`).
5. **MCP server**: stdio, same-user, localhost only; `dispatch_task` gated (§EP-14) per the lethal-trifecta rule — the ideas session reads untrusted web content and must not be able to trigger arbitrary dispatch.

## 6. Detailed specs

### EP-10 — Usage Ledger (all-provider usage history + dashboard + subscriptions)

**Problem.** The three usage readers compute rolling windows on demand and throw them away: no history survives beyond 30 days of files, no per-model / per-project / hour-of-day dimensions exist, the only surface is three Settings cards, and DryDock knows nothing about what each subscription costs or allows. "Track how I'm doing" needs a ledger, not a speedometer.

**Spec A — usage history store + collectors.**
- *Purpose.* Persist daily usage facts per provider so history accrues forever and every dashboard question becomes one indexed SELECT.
- *Data.* New table, populated by three collectors wrapping the existing readers (extended to emit per-day, per-model, per-project rows instead of window totals):

```sql
CREATE TABLE IF NOT EXISTS usage_daily (
  day          TEXT NOT NULL,            -- 'YYYY-MM-DD' local tz
  provider     TEXT NOT NULL,            -- 'claude' | 'codex' | 'google'
  surface      TEXT NOT NULL,            -- 'cli' now; 'web' | 'import' from EP-15
  model        TEXT NOT NULL DEFAULT '', -- 'claude-fable-5', 'sonnet', '' when unknown (Antigravity: parsed best-effort)
  project_key  TEXT NOT NULL DEFAULT '', -- derived from session cwd (dash-decoded), '' when unknown
  input_tokens INTEGER NOT NULL DEFAULT 0,
  cached_tokens INTEGER NOT NULL DEFAULT 0,
  output_tokens INTEGER NOT NULL DEFAULT 0,
  reasoning_tokens INTEGER NOT NULL DEFAULT 0,   -- codex only today
  total_tokens INTEGER NOT NULL DEFAULT 0,
  sessions     INTEGER NOT NULL DEFAULT 0,
  turns        INTEGER NOT NULL DEFAULT 0,
  events       INTEGER NOT NULL DEFAULT 0,       -- antigravity activity counts land here
  PRIMARY KEY (day, provider, surface, model, project_key)
);
```
  Idempotent upsert per (day×dims) — a re-collect overwrites the same rows, so partial days self-heal. Collector watermark = the existing `usage-mtime` cheap check (files with mtime older than the last collected day skip). Backfill on first run walks everything once (1.3 GB Claude walk is the known worst case; the mtime pre-filter already took the cold read from ~13s down, and backfill is once).
- *Honesty rules.* Antigravity rows carry `events`, not tokens — the UI must label them "activity" (the reader's own doc: token counts verifiably absent on disk). Unknown model/project stay `''` and render as "unknown", never guessed. Cost estimates (below) are labeled *estimates*.
- *Cost estimation (carefully).* Subscriptions don't bill per token, so **do not render token-dollars as spend**. Instead: per-provider "API-equivalent value" (tokens × current API list price, from a versioned constants module `lib/insights/api-prices.ts`) framed explicitly as *"what this usage would cost at API prices"* next to the flat subscription price — that's the "is the plan worth it" number the user actually wants. Dispatched-run `cost_usd` (already captured per run) stays the only thing called "cost".
- *API.* `GET /api/usage?window=90d&groupBy=model|project|hour` → rollup slices + freshness per connector. `runtime = "nodejs"`, on-read collect with 60s TTL + mutex.
- *Reader-gap fixes folded in* (verified against OSS prior art + provider trackers):
  - `codex-usage.ts` must also walk **`~/.codex/archived_sessions/`** (sessions Codex archives move there and silently vanish from the current walk — ccusage hit the same bug, PR #849; dedupe by relative path, not basename).
  - Probe **`~/.gemini/antigravity-cli/`** (SQLite `.db` conversation files) as a second Antigravity store — the shipped reader only sees the IDE's `brain/` logs; the `agy` CLI writes here instead. Turn counts only, labeled activity (schema is reverse-engineered; token counts confirmed absent in every Antigravity local format).
  - Defend the Claude walk against the **dash-collision** in project-dir encoding (a cwd containing `-` collides with the path-separator encoding — anthropics/claude-code#7009).
- *Tests.* Upsert idempotency (double-collect same day = same rows) · per-model/day bucketing from fixture JSONLs (all three formats, incl. malformed lines) · local-tz day boundary (UTC 03:00 event lands on the right local day) · antigravity events-not-tokens separation · watermark skip correctness · archived-sessions dedup · dash-collision fixture.

**Spec B — Usage dashboard (Analytics → Usage tab).**

- *UX flow (taps).* Header **Analytics** (existing nav link) → tab bar `Runs | Usage | Flow` (new; `Runs` = today's page unchanged). **1 tap** from anywhere in the PWA; 0 forms. Tab remembered per session.
- *Layout (mobile-first, per design.md):* stacked cards —
  1. **Provider trio strip** (reuses Settings-card visual language): weekly window bar + freshness dot each.
  2. **Model mix** — horizontal stacked bars per provider, last 30d (Claude: fable/sonnet/haiku…; Codex: static; Google: parsed selections best-effort).
  3. **Rhythm** — hour-of-day × weekday heatmap of turns (all providers), the "when do I actually use AI" punch card.
  4. **Projects** — top project_keys by tokens, 30d, cross-provider columns.
  5. **Value framing** — per provider: subscription price (from Spec C) vs API-equivalent value, labeled as estimate.
  Empty/error states mandatory: a provider with no local data renders its card with "no local data — deep link" exactly like Settings does today (no invented zeros).

Charts are CSS bars like the existing analytics page — **no chart library** (design.md "don't add libraries" rule).

**Spec C — subscription registry.**
- *Purpose.* The "subscription information" half of the ask: plan, price, renewal day, cap semantics per provider — so usage renders against what's paid for.
- *Data.* `subscriptions` table: `provider TEXT PK, plan_name TEXT, price_usd_month REAL, renewal_day INTEGER, cap_notes TEXT, updated_at INTEGER, source TEXT DEFAULT 'manual'`. Seeded by **manual entry** in Settings (three rows, one-time, ~60s of typing) — the only 100%-reliable source. EP-15 can later update `source='receipt'|'browser'` rows automatically; manual always wins on conflict.
- *Cap semantics rendered, not fetched:* Claude = 5h window + rolling weekly, shared across claude.ai/Code/Cowork; Codex = 5h rolling + weekly, token-based; Google AI Pro = daily/model quotas. Stored in `cap_notes` seeded with sensible defaults, editable — these change too often to hardcode as truth.
- *UX.* Settings → Provider budgets section gains an ✏️ per card (plan name, $, renewal). The Usage tab and BudgetWidget read it. **Clicks to first value: 3 fields typed once, ever.**
- *Tests.* CRUD via allow-listed settings route or a small `/api/subscriptions` · manual-wins-over-collector precedence.

**Spec D — live quota collectors (local subprocess surfaces — no browser, no scraping).**
- *Purpose.* The caps gate on **% of window used**, which token sums can't reproduce (Anthropic/Google don't publish denominators; Codex weights by reasoning time).
- *Status, corrected:* **only Codex has a confirmed sanctioned surface.** Claude's is a *spike*, not a deliverable — `stats-cache.json` has an undocumented schema, may carry no percentage at all, and (as it turns out) does not exist on this machine. S6/S10's "Claude weekly 85%" therefore depends on a manual check or EP-15, not on EP-10. The original wording promised both majors and was wrong; Codex flagged it on PR #8.
- *Codex (best-supported):* spawn `codex app-server` and call `account/rateLimits/read` over JSON-RPC stdio — returns primary(5h)/secondary(weekly) `usedPercent`, `resetsAt`, `windowDurationMins`, `credits.balance`, `planType`, riding the CLI's own `~/.codex/auth.json` OAuth (this is the interface OpenAI's own VS Code extension uses). Note: the rollout JSONLs can never provide this — their `rate_limits` field is confirmed always-null (openai/codex#14880). Fallback (documented, off by default): the `backend-api/wham/usage` endpoint the official CLI itself polls.
- *Claude:* spike `~/.claude/stats-cache.json` (pre-aggregated token/cost totals backing `/usage`; survives log rotation; schema undocumented — parse defensively, fall back to the JSONL walk). Cap-% is served to the CLI by a usage endpoint Anthropic acknowledges but doesn't document; do **not** call reverse-engineered paths — if stats-cache lacks the %, render window *consumption* and reset times, and leave cap-% to a manual claude.ai check (see EP-15's ToS boundary).
- *Google:* no sanctioned machine surface (Antigravity's `/usage` is a TUI panel). Render the qualitative "refreshes every 5h until the weekly cap; Pro = 4× free tier" framing + context-window ceilings — never a fabricated %.
- *Data.* `quota_snapshots` table: `provider, window ('5h'|'week'|'week_sonnet'), used_pct REAL NULL, resets_at INTEGER NULL, source ('app-server'|'stats-cache'|'manual'|'browser'), captured_at`. ### EP-11 — Code Flow (GitHub analytics + AI attribution + correlation)

**Problem.** DryDock's analytics see only DryDock-dispatched runs. The user's actual output lives in git across 34 repos — including the 7 private ones — authored by them, Claude Code, Codex, `jam/*`, and DryDock's own tasks, with no view of cadence, patterns, or AI share. (JTBD-8, S8.)

**Spec A — GitHub collectors + schema.**
- *Data.* Five tables in the R2-verified shapes (house style: TEXT PKs, epoch seconds, `idx_<table>_<col>`): `gh_repos` (node id PK, `name_with_owner`, `is_private`, `pushed_at` watermark, `last_synced_commit_date`, `drydock_project_id` link), `gh_commits` (oid PK, repo, authored/committed at, additions/deletions, `agent`, `agent_model`, `attribution_source`, `session_id`), `gh_prs` (node id PK, repo+number unique, created/merged/closed, size fields, `head_ref`, `agent`, `session_id`), `ai_sessions` (session id PK, provider, cwd, `git_branch`, repo link, start/end, model, tokens, `pr_repo`+`pr_number` from `pr-link`, `jsonl_path`), `gh_daily_stats` (day×repo×agent rollup, upserted at ingest).

Costs ~1 point/query against 5,000/hr — a 5-min TTL is far below budget. Preflight `gh auth status` once per process (10-min cache) → connector `health()` reports "gh not authenticated" as a visible state, never a silent empty dashboard.
- *Scope note.* Private commits/PRs come from direct `repository()` queries under the existing `repo` scope. `contributionsCollection` aggregates (incl. `restrictedContributionsCount`) power the headline heatmap; per-repo private detail deliberately does NOT rely on calendar visibility settings.
- *Tests.* Watermark skip/advance · pagination stop-at-seen · trailer extraction fixtures (Claude with model capture, Codex static, none) · `emails: []` guard (empty author filter silently matches nothing — regression-pin the gotcha) · daily-stats upsert idempotency.

**Spec B — attribution + correlation engine.**
- *Attribution priority per commit* (pure function, `lib/insights/attribution.ts`): 1) branch `drydock/*` → join `tasks.provider` (ground truth); 2) trailer regex — `Co-Authored-By: Claude (.*) <noreply@anthropic\.com>` (capture model) / `Co-authored-by: Codex <noreply@openai\.com>`; 3) branch prefix `claude/*`, `jam/*`, `codex/*` (coarse, per-PR); 4) unattributed = human. `attribution_source` records which rule fired — the UI shows confidence, and **"trailer coverage"** itself becomes a rendered metric (research: trailer-only detection catches ~20% of true AI involvement in the wild; coverage transparency beats false precision).

- *Tests.* Priority order (drydock branch beats conflicting trailer) · model capture variants · pr-link exact join · window fallback incl. grace edge · worktree→repo resolution.

**Spec C — Flow dashboard (Analytics → Flow tab).**
- *UX flow.* Same 1-tap tab. Cards: **heatmap + streaks** (private-inclusive; streak computed from own `gh_commits`, not the calendar) → **AI share** (weekly stacked area: human/claude(by model)/codex/jam/drydock + coverage chip) → **cadence** (rolling 7d/28d commit lines; PR cycle time split self-merged vs reviewed, median + p90) → **punch card** (hour×weekday, filterable "mine only" vs "agents" — unfiltered punch cards lie once agents commit at 3am) → **repo/language mix** (30d) → tap-through: any PR row → originating session (model, cost, follow-up count) when correlated.

- *Tests.* Streak math across tz boundaries · AI-share aggregation · cycle-time split · "mine only" filter.

### EP-12 — Capture Everywhere (inbox + quick-add + Siri + iMessage)

**Problem.** Capture today means unlock → app → form (or a Notes line). The ask: "a simpler way of adding" — texting yourself, Siri, one tap — and a stage that keeps raw captures from polluting the trusted backlog. (JTBD-9/10, S7.)

**Spec A — inbox stage + parse conventions (the model change).**
- *Data.* `backlog_items.triaged_at INTEGER NULL` (`ensure()`), `backlog_items.raw_capture TEXT NULL` (original text preserved verbatim — parsing is best-effort, never destructive), `source` union extends with `'shortcut' | 'imessage' | 'ai-generated'` (+ `'github'` in EP-13; no CHECK constraint exists, application-layer change), `status` union gains `'proposed'` for AI-generated rows (EP-14). **Inbox = `triaged_at IS NULL`.** Existing rows: a one-time migration stamps `triaged_at = created_at` (everything already in the list was implicitly triaged — no behavior change for current data).
- *Parsing* (`lib/orchestrator/capture.ts`, pure): optional trailing markers only — `#<project-slug>` (fuzzy match against project names; unmatched → NULL project, marker kept in title), `p1`–`p4` → priority. Everything else stays title. Missing markers never block capture (GTD: capture is permissive, clarify later).
- *Triage UX.* `/backlog` gains an **Inbox (n)** section above the filters, each row: parsed title + source chip + **Accept** / **✏️ edit-then-accept** / **🗑️**. Accept stamps `triaged_at` (and, once EP-13 ships, mirrors to the tracker repo). **Taps per triaged item: 1** (accept) — the whole inbox sweep for a typical morning (3–5 items) is under 30 seconds. Notes-sourced lines keep bypassing the inbox (they're deliberate typed entries in a trusted surface — behavior unchanged).
- *Tests.* Marker parsing (all/none/garbled) · inbox filter · migration stamps existing rows · accept transition · raw_capture preserved.

**Spec B — capture endpoint + PWA quick-add + Shortcut/Siri.**
- *API.* `POST /api/capture` `{text, source, idempotency_key?}` → creates inbox row, returns `{id, parsed}`. Auth: existing middleware (Bearer `DRYDOCK_AUTH_TOKEN` / CF Access / localhost). Idempotency key (client-generated) dedupes Shortcut retries. 202-fast: no Notes push on capture (inbox rows aren't in the Note; only accepted rows sync — keeps the sacred Notes path untouched).
- *PWA quick-add.* FAB on `/backlog` (and dashboard) opens a **single-field** sheet (one input + Add; markers inline) — replaces nothing, sits beside the existing full form. **Taps: 2** (FAB → type → Add).
- *Shortcut/Siri.* A documented Shortcut (`docs/setup.md` §8, with screenshots): trigger phrase "quick add" → `Ask for Input` (becomes **voice dictation** when invoked via Siri — the only zero-unlock channel) → `Get Contents of URL` POST with the Bearer header → success chime; failure branch appends to a designated Apple Note ("Capture fallback") so an unreachable tunnel never loses a thought. Token note: lives in the Shortcut config; rotating `DRYDOCK_AUTH_TOKEN` means re-editing it (documented).
- *Tests.* Endpoint auth paths · idempotency replay · parse integration · (Shortcut itself is doc-verified, not unit-tested — stated honestly).

**Spec C — iMessage-to-self poller (the "text myself" channel).**
- *Mechanics.* `lib/integrations/imessage.ts`: poll `~/Library/Messages/chat.db` (read-only, WAL-safe) every 60s for `is_from_me=1` messages in the self-conversation, `ROWID > settings.imessage_last_rowid_seen`. **Self-handle is user-configured** (`settings.imessage_self_handle`, one Settings field) — auto-detection is unreliable by design. Text extraction: `text` column, falling back to `attributedBody` (typedstream) via a **vendored minimal decoder with fixture tests** — flagged as the fragile part; decoder failures surface as "capture arrived, text unreadable — open Messages" inbox rows (raw preserved), never dropped silently. Confirmation reply "✅ captured: <title>" via `osascript` (Messages AppleScript — same trust pattern as Apple Notes).
- *Preconditions & honesty.* Works while the server runs from an FDA-granted terminal (current reality). A future launchd-managed DryDock breaks TCC inheritance — documented caveat in setup.md, and the connector `health()` reports "no Full Disk Access" explicitly (probe: can we open chat.db) instead of an empty inbox.
- *Why last in this epic:* highest fragility (typedstream, macOS updates, TCC) for a channel whose UX (~4–6s, requires unlock) Siri already beats. Ship A+B first; C when the core is boring. Prefix convention: only messages starting with a configurable trigger (`idea:` default, or capture-all toggle) become rows — texting yourself groceries shouldn't.
- *Tests.* Rowid cursor advance · self-chat filter · prefix filter · attributedBody fixtures (Ventura+ shapes) · unreadable-body honesty path.

### EP-13 — Durable Mirror (GitHub Issues spoke)

**Problem.** The backlog's durable copies are one SQLite file and one Apple Note. The ask: "issue form or something more durable." (JTBD-10.)

**Spec A — the spoke.**
- *Topology (decided):* hub-and-spoke, DB hub — **a single private tracker repo** (`pranava0x0/backlog`), one issue per **triaged** backlog item (inbox/proposed rows never leave the DB — the durable tracker stays clean). Labels: `project:<slug>`, `source:<source>`; open/closed IS the status (no status labels — no second truth). Per-project repos are NOT used for backlog items (cross-project prioritization is the point of the global backlog); an optional per-repo issue at burn-down time is a small EP-3 add-on (`gh issue create` beside the PR, default off) for repo-local paper trail.
- *Mechanics.* `lib/integrations/github-issues.ts` via `gh issue create/edit/close/list --json` subprocess (no tokens in DryDock). `backlog_items.github_issue_ref TEXT` (`"owner/repo#42"`) stamped after first push — the `apple_notes_note_id` pattern per-row; recovery breadcrumb `<!-- drydock:id:<id> -->` appended to the issue body (Probot metadata pattern). Sync = pull-then-push inside the **same** orchestrator tick and mutex as Notes (sequential: notes → github; they mutate the same rows — one mutex, zero new race classes). Echo-loop safety: pull diffs remote against *current DB state* (identical philosophy to Notes — no snapshot column needed).
- *Conflict rules* (extending the cheat sheet):

| Scenario | Resolution |
|---|---|
| Add in DB (triage-accept) | push creates issue, stamps ref |
| Add issue on GitHub directly | pull creates row `source='github'`, pre-triaged (deliberate act on a deliberate surface) |
| Done/🗑️ in DryDock | close issue (`completed` / `not planned` + comment). Never deletes the issue — closing is the durable analog of the DELETE-is-DB-only rule |
| Issue closed on GitHub | DB → `done` |
| Issue **reopened** on GitHub | DB → back to `idea` — **bidirectional by design**, diverging from the Notes irreversibility rule because reopen is a deliberate, timestamped, logged action with none of a checkbox's ambiguity. (Product call — flagged in §8 if uniform-rule is preferred.) |
| Title/body edited either side | DB wins on push; GitHub-side edits pull straight in by issue number (no rename heuristic needed — stable ids make this spoke structurally simpler than Notes) |
| gh unauthenticated / offline | structured error, per-spoke ⚠ in `SyncStatus` (badge becomes two-dot: Notes · GitHub), everything else keeps working |

- *Freshness.* Poll on the existing 30s `/backlog` cadence (2–3 `gh` calls/tick — trivial against limits). Optional later: reuse DD-BL-31's planned `POST /api/webhooks/github` (HMAC-verified) for `issues` events — latency nicety, not a requirement.
- *UX.* Zero new required screens: a one-time Settings field (tracker repo, with a "create it now" button running `gh repo create --private`), the second sync dot, and each backlog row linking out to its issue. **Clicks added to daily flow: 0.**
- *Tests.* Ref stamping · echo no-op (push then pull = no changes) · close/reopen both directions · breadcrumb recovery (ref lost → re-adopt by comment) · sequential-tick mutex · degraded-mode honesty.

### EP-14 — Link the Fleet (MCP server, ideas intake, briefing, reply-to-act)

**Problem.** Three systems, zero links: autogenerated-ideas writes specs nightly (03:33, run 113 and counting) that nothing reads; Daily Briefing is dead (last output 2026-05-24, scheduler gone); DryDock can't be driven by either. (JTBD-11, S9.)

**Spec A — DryDock MCP server (DD-BL-34, scoped down).**
- *Shape.* `drydock-mcp` stdio entry point (`npx tsx mcp/server.ts` or a small compiled bin), registered once per satellite: `claude mcp add --scope user drydock -- node <path>`. **Talks to the DB through `lib/db/*` directly** (same-process import, own connection) — deliberately NOT through the HTTP API, so 7am jobs don't depend on the Next.js server being up (the server-keepalive gap becomes non-blocking for the fleet; still worth fixing — see Spec D).
- *Tools v1 — **allowlisted per caller**, corrected after Codex's P1 on PR #8.* Withholding `dispatch_task` alone was not enough: `list_backlog`, `list_tasks`, and `get_usage_stats` pull private local state into the context of a session that is already reading attacker-controlled pages and has its own web access to send it back out, and `burn_down_item` mutates. The **`ai-generated` caller now receives `add_backlog_item` and nothing else** — its blast radius really is "propose spam into the inbox". The list below is the *human-driven* caller's surface:
- *Tools v1 (read + propose only, manual caller):* `add_backlog_item({title, description?, project?, source})` (source forced to the caller's registered identity, lands `proposed` for `ai-generated`), `list_backlog({status?})`, `get_usage_stats()` (wraps EP-10 rollups + analytics summary), `list_tasks({status?})`, `get_task_status({id})`, `burn_down_item({id})`. **`dispatch_task` is NOT exposed in v1** — the ideas session consumes untrusted web content; giving it dispatch is the lethal trifecta. Burn-down creates a *pending* task (human runs it), which is the existing safety line.
- *Tests.* Tool schemas · source forcing · proposed-status landing · a prompt-injection tabletop test in the docs (what CAN a hostile page reach: propose spam → inbox, sweepable; nothing executes).

**Spec B — ideas connector (autogenerated-ideas → inbox).**
- *Mechanics.* The nightly skill gains one step (its SKILL.md edited once): after writing/refreshing a spec, call `add_backlog_item` with the spec title + 1-line pitch + `file://` path in description. Fallback (if the MCP call fails): DryDock-side folder connector `lib/connectors/ideas-folder.ts` scans `~/Projects/autogenerated-ideas/*.md` mtimes on the usual TTL and syncs new/refreshed specs — **both paths land identically** as `source='ai-generated', status='proposed'`.
- *Dedup before insert* (`lib/orchestrator/capture.ts`): exact title (existing `getBacklogItemByTitle`) then word-shingle Jaccard ≥ 0.6 against non-dropped rows — ambiguous matches **insert with a "possibly similar to #n" note, never silently drop** (false-positive dedup is the silent failure the house rules ban). Spec-refresh of an already-linked idea updates the existing row's description, not a new row (external_id = spec filename).
- *Triage.* `proposed` rows show in the Inbox with a 🤖 chip; **Accept** promotes to `idea` (→ EP-13 mirror), 🗑️ drops. Ideas older than 30 days un-accepted auto-archive (`dropped`) — the anti-pollution timeout, surfaced in the digest as a count, reversible via the GitHub-reopen path… (no — archived proposals never reached GitHub; reversal = re-propose. Stated plainly in the UI copy.)
- *Tests.* Jaccard thresholds (near/far titles) · flag-don't-block path · refresh-updates-row · timeout archive.

**Spec C — briefing contract + digest + reply-to-act.**
- *Revive Daily Briefing as a consumer, not a fork.* The briefing job (a Claude Code **Desktop Scheduled Task**, ~7:00am, with the documented missed-window guardrail in its prompt: "if after 5pm, summarize what was missed instead") composes: **needs-attention** (SQL via `list_tasks` — failed/gate-failed/queued-stale) → **usage/budget** (`get_usage_stats` — weekly windows, budget %) → **proposed ideas** (top 3 + count) → its existing calendar/email/messages sections. Two-tier cost discipline: every DryDock section is deterministic SQL through MCP tools; the LLM writes prose only. Output: the dated markdown in `~/Projects/Daily Briefing/` (unchanged contract) **plus** delivery.
- *Delivery rails, in shipping order:* (1) **EP-5 webhook** (ntfy.sh — an afternoon, already specced in the base plan) for the buzz; (2) **iMessage via the existing Messages AppleScript** (`send_imessage`-style osascript to self) for the digest text — zero new secrets; (3) **reply-to-act**: a persistent `claude --channels imessage` "inbox session" on the Mac maps replies (`accept N` / `drop N` / `burn N` / `brief`) to MCP calls. Replies that would *dispatch* (`burn N` creates a pending task; a future `run N`) always confirm back before acting on anything beyond burn-down — the never-auto-escalate allowlist.
- *Provenance chain (now complete):* spec file → `backlog_items(source='ai-generated')` → `triaged_at`/issue ref → `task_id` → `runs.parent_run_id` chain → (EP-3) `pr_url`. One query answers "which nightly idea became shipped code."
- *Missing operations (flagged by Codex, PR #8).* The v1 MCP surface has no `accept` or `drop`, yet this channel promises to map `accept N` / `drop N` onto MCP calls — so as specified only `burn N` and `brief` are buildable. Reply-to-act needs two more explicitly-scoped mutations, `triage_backlog_item` and `drop_backlog_item`, added to the **manual** caller's allowlist only. They must never reach the `ai-generated` caller: accepting a proposal is precisely the human gate the inbox exists to enforce, and a session reading untrusted pages must not be able to approve its own suggestions.
- *Tests.* Digest section builders (pure, fixture DB) · reply-command parser (incl. hostile/garbled replies → "didn't understand", never a guessed action) · guardrail behaviors.

**Spec D — keep the host alive (small, standalone).**
- launchd `KeepAlive` plist for the Next.js server (prod build) + the tunnel — documented in setup.md §6 with the TCC caveat from EP-12C (FDA-bearing terminal vs launchd: the iMessage connector may need the terminal path; everything else is TCC-free). Watchdog note: scheduled jobs that depend on local surfaces log-and-alert via the EP-5 webhook when a dependency is down, instead of failing silently. *This is the one item in the track that exists purely to make 7am automation trustworthy.*

### Where the plan was wrong, and what the data said

1. **`~/.claude/stats-cache.json` does not exist** on this machine, despite
   1,673 session logs. Spec D assumed it would. The probe ships and
   degrades honestly; cap-% is simply unavailable until a Claude Code
   build writes that file.
2. **`codex` is not on PATH.** This user drives Codex through the desktop
   app and the VS Code extension (`originator: "Codex Desktop"`,
   `source: "vscode"` in the rollout metadata), so `codex app-server`
   can't be spawned. Same honest degradation.
3. **Codex usage *does* split by model.** The plan said "Codex: static".
   `turn_context` carries `payload.model` (`gpt-5.6-sol`, `gpt-5.5`) and
   `payload.cwd`, and precedes the `token_count` events it configures —
   so there's a real model mix and real project attribution.
4. **Archived Codex sessions can't be deduped by relative path.** The
   plan assumed the archive mirrors the date tree; it's flat, so a moved
   rollout has a different relative path in each root. The session UUID
   embedded in the filename is the only thing that survives the move.
5. **The dash collision is worse than "ambiguous" — it's actively
   wrong.** A real directory here decodes to a project called "Robotics";
   the session's own `cwd` says "Robotics Leadership". We never decode.
6. **A `Co-Authored-By` trailer does not imply AI.** Human co-author
   trailers are common in these repos. The `noreply@` **domain** is the
   discriminator; matching on the name would have inflated the AI share
   with the user's own commits.
7. **Local git beats the GitHub API for EP-11.** Attribution needs full
   message bodies, which `gh search commits` doesn't reliably return —
   the API path would have yielded no model breakdown at all.
8. **The first usage collect blocked for 83 seconds** (270 large session
   logs, all recent enough that the mtime pre-filter can't skip any).
   `/api/usage` now collects in the background and reports `collecting`.

### Known data problem in the user's DB

The `projects` table holds **stale paths** — rows point at
`~/Documents/Projects/...` while the real location is `~/Projects/...`.
The project-backlog connector reports this explicitly rather than
claiming "no backlog file". Re-importing from `/discover` fixes it.

### Two more things the data corrected

9. **`attributedBody` is not an edge case.** The plan called the
   typedstream decoder "the fragile part". On this Mac **497,612 of
   949,169 messages (52%)** have a NULL `text` column — so it isn't a
   fallback, it's the main path. The decoder was validated against 4,000
   messages carrying both fields (4,000 exact matches, 0 mismatches)
   before being trusted.
10. **Idea specs get merged in place.** 7 of 78 keep their filename and
    restyle the heading to `# ~~Name~~ — MERGED into #67`. Reading titles
    naively would re-propose a dead idea every night, forever.
