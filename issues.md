| DD-010 | 2026-07-11 | (EP-2, caught by a unit test) `getLatestRunForTask` ordered by `started_at DESC` only. `started_at` is `unixepoch()` seconds, so a follow-up run created in the same second as its parent tied — the query could return the *parent*, meaning the SSE route would stream the wrong run and `session_id` capture would read the wrong row. | Added a `rowid DESC` tiebreak to `getLatestRunForTask` and `listRunsForTask` ([lib/db/runs.ts](lib/db/runs.ts)). Same class as the queue's FIFO tiebreak (DD-none). Regression covered by `followup.test.ts` "captures a fresh session id from the follow-up run". |
| DD-009 | 2026-07-11 | During EP-1 browser verification, `POST /api/tasks/[id]/cancel` returned `alreadyTerminal` while the task was still running — cancel appeared broken. | Not a code bug: `next dev` gives route handlers separate module instances, so the `/cancel` route's `ACTIVE_RUNS` map didn't hold the controller the `/run` route registered. Confirmed working in a production build (`npm run build && npm start`): cancel returns `{cancelled:true}`, task→failed, `failure_reason='cancelled'`, partial output preserved. Documented the dev-mode caveat in AGENTS.md; verify cancel/SSE-abort against a prod server, not dev. |
| DD-001 | 2026-05-12 | SSE stream hung indefinitely when subscribing to a run whose hub history was wiped (Next.js dev HMR) — the subscriber waited forever on a freshly-created empty entry. | [app/api/tasks/[id]/stream/route.ts](app/api/tasks/[id]/stream/route.ts) now branches on `getActiveRunController(runId)`; terminal runs replay from the DB directly instead of subscribing. Caught by curling the endpoint during browser-preview verification. |
| DD-002 | 2026-05-12 | Stream-route fallback enqueued `runs.output` only, so a failed run with empty stdout (spawn ENOENT) showed nothing in the UI. | Added `error` replay to `replayFromDb()` in [app/api/tasks/[id]/stream/route.ts](app/api/tasks/[id]/stream/route.ts). Verified in preview: failure now renders the stderr line + exit code. |

Shipped in commit `f8bf59d`. |
| DD-004 | 2026-05-14 | Apple Notes sync silently created a duplicate `DryDock Backlog` note on *every* transient AppleScript error. | DD-006 | 2026-05-14 | Even with V3, the `/backlog` page polling appeared to keep creating new notes.
